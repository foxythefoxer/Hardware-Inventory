# Prompts for consuming `hw-inventory.sh` output

The script emits Markdown with YAML frontmatter specifically so the output can be filed
in a notes system and handed to an LLM as machine context. These two prompts are what
that looks like in practice.

Adapt the file paths and note names to your own setup — they are placeholders.

---

## Prompt A — normalise a run into a note

Paste this, then the raw script output.

```text
Below is raw stdout from hw-inventory.sh, a read-only hardware inventory script.
Convert it into a single note.

OUTPUT CONTRACT
- Return the complete note in one fenced markdown block, nothing else around it.
- Preserve the YAML frontmatter as generated. Fill `role:` from context. Leave
  `collected:` exactly as generated — never restamp it to today. That field is how
  staleness is detected; rewriting it destroys the signal.
- Keep every table. Do not summarise tables into prose.
- Keep the fenced code blocks (kernel cmdline, df/findmnt, lspci, docker) verbatim.
  They are raw evidence and need to stay greppable.
- Add no facts that are not in the output. "—" and "(needs root)" stay as-is; absence
  of data is itself information.

OBSERVATIONS
End with an `## Observations` section. Check at minimum:
- SMART: non-zero Reallocated or Pending sectors, health not PASSED/OK, NVMe wear
  above 80%, power-on hours past ~40,000 on a spinner.
- Unraid: array state not STARTED, any disk not DISK_OK, missing/invalid/disabled
  disks, non-zero sync errors, an array disk above ~90% full.
- Memory: DIMMs unevenly spread across channels, mismatched part numbers or speeds,
  running below the DIMM's rated speed.
- Network: a link negotiated below the NIC's capability, an interface DOWN that
  should be up.
- Kernel cmdline: vfio-pci or amd_iommu/intel_iommu flags present but IOMMU reported
  inactive, or the reverse.
- Filesystems: a mount above ~85%, a ZFS pool not healthy, btrfs showing a missing
  device.
- Failed systemd units.
- Anything internally contradictory.

State what the data shows and why it might matter. Do not recommend a fix unless
asked. If nothing stands out, write "Nothing anomalous." and stop — do not manufacture
findings to fill the section.

RAW OUTPUT FOLLOWS:
```

## Prompt B — use existing notes as reference

Paste at the top of a session where you're attaching one or more host notes.

```text
The attached notes are hardware inventories generated by a read-only script. Treat
them as ground truth about my hardware.

USING THE DATA
- Check `collected:` first. If a note is more than a few months old, say so once when
  it becomes relevant. Kernel version, uptime, disk usage and container state drift
  fastest; hardware fields drift least.
- "—" and "(needs root)" mean unknown, not absent. Ask, or tell me which command
  fills the field. Don't assume a default.
- Match the actual OS per host — package manager, init system and filesystem all
  differ. Never give me a systemd command for a host that doesn't run systemd.
- Identify disks by serial, not by /dev/sdX from an old run. Kernel device letters are
  not stable across reboots.
- When something spans hosts, say which host each step runs on.

BEFORE SUGGESTING A COMMAND
- Say whether it reads or writes. If it writes, say what changes and how to undo it.
- Flag anything that needs a reboot, drops a link, or interrupts a service, before the
  command rather than after.
- Say whether a step will spin up disks that are in standby, or requires stopping an
  array.
- If a step takes down something other hosts depend on — DNS, a reverse proxy, the
  gateway — say so first.

WHEN THE NOTES DISAGREE WITH ME
Say so. Don't silently reconcile. If I say a box has 64 GB and the note says 32, surface
the conflict — one of us is wrong and I want to know which.
```

## Why `collected:` is pinned

Both prompts forbid updating that field. An LLM normalising a six-month-old paste will
helpfully stamp it with today's date, and the archive quietly stops being trustworthy —
every note claims to be current, so staleness can no longer be detected at all.

## Why "Nothing anomalous" is mandated

Without an explicit instruction to produce an empty finding, models pad the section.
Once a few notes contain invented findings, the section stops being read, and the one
run that surfaces a real failing disk gets skimmed past with the rest.

## Diffing runs

Volatile fields are grouped under `### Snapshot` so they can be excluded:

```bash
diff <(sed '/^### Snapshot/,/^$/d' old.md) \
     <(sed '/^### Snapshot/,/^$/d' new.md)
```
